# MediAgent AI — Plan to Make the Project Run End-to-End

**Date:** 2026-09-20
**Source:** `docs/CODEBASE_VS_EDI_ANALYSIS_2026-09-20.md` gap audit + live verification of server/Docker/Python wiring.

## Current state (what blocks "end-to-end" today)

1. **Runtime blocker:** `docker-compose` runs `node server/index.js`, but the Dockerfile never compiles TS → there is **no `server/index.js`**. `server.ts` is ESM TypeScript; the Docker image only copies `server/` source.
2. **Firestore blocker:** `server/services/firestore.ts` imports the **client** SDK (`firebase/app`) for server use, while `docker-compose` injects `FIREBASE_SERVICE_ACCOUNT_KEY` (admin pattern). No `firebase-admin` dep exists. Server persistence is broken as wired.
3. **Python service is orphaned:** `python_service/app.py` exposes `/rag/search`, `/ocr/extract-lab`, `/calibrator/predict`, but **nothing in `server/` calls it**. The runtime RAG still uses the old in-memory Gemini path.
4. **Demo data undermines the model:** flagship demo cases feed SVG cartoons to the real DenseNet-121, producing meaningless probabilities.

## Goal
One command (`docker-compose up` or `npm run dev` + uvicorn) brings up: React UI → Express API → 5 agents → **real ChromaDB RAG + FastAPI calibrator** → Firestore persistence → calibrated report, with demo cases that exercise the real model.

## Phases

**Phase 0 — Boot fixes (make it start)**
- Add a server build step: emit compiled JS (esbuild/tsc) to `server/dist` and point `Dockerfile` `CMD` at it; OR run `server.ts` via `tsx`. Fix `package.json` `start`.
- Decide Firestore mode: switch `server/services/firestore.ts` to `firebase-admin` using `FIREBASE_SERVICE_ACCOUNT_KEY`, OR keep client SDK and drop the admin env. Pick **admin** for server. Add dep.

**Phase 1 — Wire Express → Python service**
- Add `PYTHON_SERVICE_URL` env (default `http://python_service:8000` in compose / `http://localhost:8000` local).
- Create `server/services/pythonService.ts` client with `/health` fallback: if Python is down, degrade gracefully to existing in-memory path.
- Replace the hardcoded-10-guideline Gemini RAG in `server/rag/` with calls to `/rag/search` (ChromaDB + fine-tuned retriever). Keep Gemini only for LLM reasoning, not retrieval.

**Phase 2 — Calibrated confidence**
- In `server/agents/doctor.ts`, extract the pipeline features and call `/calibrator/predict`; use the **calibrated** value as `probabilityScore`. Keep the deterministic 4-pillar `ConfidencePillarScore` as the display breakdown. Add urgency cross-check as a WARNING on disagreement (never silent override).

**Phase 3 — Real demo inputs**
- Replace SVG demo images with real de-identified chest X-rays (NIH ChestX-ray14 samples) so the ONNX model produces meaningful activations; regenerate Grad-CAM per case.

**Phase 4 — One-command run & verification**
- Fix `docker-compose` to be reproducible from clean clone (vendor or fetch the gitignored `training/exports` + `chroma_db` artefacts, or document a `training` bootstrap step).
- Add a smoke script (`scripts/smoke.ts`) that: hits `/api/health`, runs one demo case end-to-end, asserts `probabilityScore` is calibrated + citations present.
- Document the exact run steps in README (env vars, two processes, ports 3000/8000).

## Verification
- `docker-compose up --build` from a clean clone → app loads, a demo case produces a calibrated report with real retrieval citations.
- `npm run dev` + `uvicorn python_service.app:app` locally → same result.
- Smoke test passes; urgency disagreement surfaces as a visible warning.

## Out of scope (separate work)
- Improving weak model metrics (retriever zero-lift, lab-NER F1 0.27, calibrator AUC 0.551).
- Adding an automated test suite.
